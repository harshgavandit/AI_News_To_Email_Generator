# World Tech Brief release operations

The Vercel project serves static HTML, CSS, and JavaScript from `public/` and routes API requests to FastAPI in `app/server.py`. There is no TypeScript or JSX build. Run `npm run build` and `npm run lint` to validate the static assets. Run `uv sync --frozen`, `uv run ruff check app tests scripts main.py`, and `uv run pytest -q` for Python. Start a local server with `uv run uvicorn app.server:app`.

Set `NEWS_DATABASE_URL` to a pooled PostgreSQL connection with TLS. For a new or upgraded database, call the owner-authenticated `POST /api/admin/setup` before promotion. It creates missing tables and preserves existing rows. The public mail flow uses a verified inbox session and does not use `ADMIN_TOKEN`. That token remains available for owner tools and the legacy fixed-recipient send route.

Configure `PUBLIC_ORIGIN`, `MAIL_SESSION_SECRET`, and the Turnstile site and secret keys before enabling `PUBLIC_EMAIL_ENABLED=1`. Use `MAIL_PILOT_MODE=0` for public delivery. Configure one of Resend (`RESEND_API_KEY`), Postmark (`POSTMARK_SERVER_TOKEN`), SMTP (`SMTP_URL` or `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, optional `SMTP_PORT`), or Gmail (`MY_EMAIL`, `APP_PASSWORD`). Set `MAIL_FROM` to a verified sender for transactional mail. Provider acceptance does not establish inbox placement.

The verified mailbox quota is three digests per UTC day across instant and scheduled sends. Public email and webhooks share a five-dispatch rolling hour per IP, with a separate limit per destination. Application-wide safety limits are 60 outbound emails, 45 digest emails, and 60 new AI briefs per UTC day. Maintain these limits until the provider and operating budgets support higher traffic.

The refresh workflow calls `GET /api/jobs/refresh` and then `GET /api/jobs/morning` with the dedicated `FEED_REFRESH_SECRET`. The native daily Vercel refresh remains a fallback for feeds. Morning dispatch uses the selected IANA timezone and processes up to three due mailboxes per invocation. GitHub Actions timing and provider capacity affect arrival. A delivery with an uncertain provider response is not replayed automatically. Recurring briefs include an unsubscribe footer and one-click unsubscribe headers.

Common Reading Room pages use a one-minute cache and can serve the previous page for another minute while revalidating it. The visible Reading Room checks for updates every minute when the reader is on the first page and is not using its controls. When the last archive check is at least 15 minutes old, a reader request can kick off a background publisher refresh. It shares the database lease and cooldown with scheduled refreshes. Force reload bypasses the page cache and can retry failed feeds. `GET /api/ready` independently checks the archive and returns HTTP 503 when all enabled feeds are stale or unavailable. `GET /api/health` checks API liveness and service configuration.

Briefs use a 30-minute cache keyed by their inputs, including persona and ordered pins. Configure both `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` for sharing across Vercel instances. Without Redis, caches are bounded per warm process. Shared rate limits still live in PostgreSQL. Verify throughput, latency, and provider quotas in an isolated environment before committing to a 10,000-user target.

Workspace dispatch accepts supported HTTPS Slack Incoming Webhook and Teams Workflows URLs. The supplied secret URL only lives for the delivery request. The stored record uses its hash. Teams Workflows must be configured to accept webhook requests for the target channel.
