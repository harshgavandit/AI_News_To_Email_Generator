# Informa AI release operations

## Research Desk and monitoring

Apply `POST /api/admin/setup` before serving the alert inbox. The additive tables hold browser session hashes, watch terms, and source references. The worker shares the existing intelligence scheduler and processes a bounded batch with its own database lease. It runs before indexing and briefing generation, so provider availability does not determine whether watches are checked. Monitor `monitoring_status`, `watches_checked`, and `alerts_created` in job output.

The unified Inbox adds the `brief_monitor_delivery` table for per-watch mute and snooze settings. Run the same owner setup on an existing PostgreSQL archive before releasing the new Inbox controls. Readers can still use the existing alert list while setup is pending. The offline reader-quality replay runs in CI and uses attributed historical facts with controlled replay dates and variants. It exercises grouping, material revisions, scoped ranking, and citation validation without contacting a model or publisher.

Readers opt in explicitly, can follow up to six queries, and can delete their background watches under Privacy & controls. Sessions expire after 30 days of browser inactivity, alerts expire after 14 days, and each inbox retains up to 60 alerts. A scheduler invocation checks at most 48 watches within a 30-second monitoring budget. Higher watch volume can lengthen the polling interval. Alert freshness also depends on the source's ingestion cadence and publisher availability. Source references include publisher names and original article links, and independent reporting on one development can be grouped under one alert.

The Research Desk can download source notes as Markdown. It displays the cached AI edition when available and a labeled publisher-evidence edition while that generation is pending. Existing OpenAI settings and quota controls continue to power semantic search and synthesis. Background watches, source selection, and trend-window comparisons run without model calls.

If using HTML file verification, publish Google's supplied file unchanged under `public/` and keep it served after verification. Submit `sitemap.xml` in the property's Sitemaps report. Use URL Inspection to test and request indexing of the homepage and source directory.

The production homepage uses the Google HTML meta-tag verification method. Keep its `google-site-verification` tag in `public/index.html` while this Search Console property needs verification.

Optional Vercel Web Analytics is off by default. Readers can opt in on `/privacy.html`; the shared loader checks the saved choice and honors Global Privacy Control and Do Not Track before loading the insights script. A `beforeSend` hook strips query parameters and fragments from event URLs and drops events when consent is withdrawn. Changing consent reloads the page, and other open tabs also reload to apply it. Hosting and security logs are separate from optional analytics. See [Vercel Analytics privacy information](https://vercel.com/docs/analytics/privacy-policy).

Vercel Speed Insights uses a separate **Performance metrics** choice on the same page and the same URL redaction and browser privacy controls. Its script is served at `/_vercel/speed-insights/script.js` on Vercel. Verify collection on the deployed site by opting in in a test browser and leaving or switching away from a page, then checking the request to `/_vercel/speed-insights/vitals`. [Vercel Speed Insights troubleshooting](https://vercel.com/docs/speed-insights/troubleshooting)

Vercel BotID Basic protects AI-assisted technology watch drafting in the Research Desk. Vercel Routing Middleware checks `POST /api/intelligence/watch-draft` before FastAPI handles it. Readers can set watch filters directly if verification is unavailable. The browser bundle is checked in so Git-based Vercel deployments can publish it with the static assets. Run `npm run build:botid` after changing the client setup or updating the SDK. Verify that a Git-based preview serves the bundle and that an empty draft in the browser reaches input validation without calling the AI provider. [Vercel BotID setup](https://vercel.com/docs/botid/get-started)

The sitemap lists the two canonical public pages. API responses carry `X-Robots-Tag: noindex` while remaining available to crawlers that render the Reading Room. If the production domain changes, update both pages' canonical URLs, `public/robots.txt`, and `public/sitemap.xml` together.

The Vercel project serves static HTML, CSS, and JavaScript from `public/` and routes API requests to FastAPI in `app/server.py`. Run `npm run build` and `npm run lint` to validate the static assets. Run `uv sync --frozen`, `uv run ruff check app tests scripts main.py`, and `uv run pytest -q` for Python. Start a local server with `uv run uvicorn app.server:app`. The existing deployment config sets `maxDuration` to 120 seconds. Confirm the target project supports this duration before promoting a deployment. [Vercel function duration](https://vercel.com/docs/functions/configuring-functions/duration)

Set `NEWS_DATABASE_URL` to a pooled PostgreSQL connection with TLS. Run the owner-authenticated `POST /api/admin/setup` before promotion. The additive discovery upgrade backfills normalized search fields and author keys on retained stories. It also creates `brief_article_feeds` to retain the feeds observed for each canonical article during ingestion. A PostgreSQL advisory lock serializes competing discovery upgrades. The archive role needs permission to create tables and to alter and index the articles table. Run setup before opening traffic where possible, since the first backfill holds a table lock. The public mail flow uses a verified inbox session. `ADMIN_TOKEN` protects owner tools and the fixed-recipient send route.

The workspace update adds nullable `source_eligible` to the articles table. Setup and the first discovery request backfill it using the reviewed source path and title rules. The upgrade preserves article identifiers and retained records, and discovery excludes records outside those rules. Run setup during a low-traffic period to finish the backfill before serving the workspace. The daily briefing endpoint uses this same eligible archive. Its selection and browser-local read state require no new service configuration.

Configure `PUBLIC_ORIGIN`, `MAIL_SESSION_SECRET`, and the Turnstile site and secret keys before enabling `PUBLIC_EMAIL_ENABLED=1`. Use `MAIL_PILOT_MODE=0` for public delivery. Configure one of Resend (`RESEND_API_KEY`), Postmark (`POSTMARK_SERVER_TOKEN`), SMTP (`SMTP_URL` or `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, optional `SMTP_PORT`), or Gmail (`MY_EMAIL`, `APP_PASSWORD`). Set `MAIL_FROM` to a verified sender for transactional mail. Provider acceptance does not establish inbox placement.

The verified mailbox quota is three digests per UTC day across instant and scheduled sends. Public email and webhooks share a five-dispatch rolling hour per IP, with a separate limit per destination. Application-wide defaults are 60 outbound emails, 45 digest emails, 20 verification emails, and 60 new AI briefs per UTC day. With an explicit Resend key and sender, set `MAIL_OUTBOUND_DAILY_LIMIT`, `MAIL_DIGEST_DAILY_LIMIT`, and `MAIL_VERIFICATION_DAILY_LIMIT` only to levels supported by the provider and budget. The Gmail fallback keeps its original ceilings.

The GitHub workflow targets publisher synchronization every five minutes, using `FEED_REFRESH_SECRET` for `GET /api/jobs/refresh`. Each invocation checks at most 64 due sources and twelve feeds per host, with two concurrent fetches per host. Each workflow runs up to two batches; any backlog resumes on the next tick. Cadences range from five minutes for advisories/status to longer intervals for quieter publishers. Conditional HTTP requests and publisher backoff reduce traffic. GitHub can delay or skip scheduled starts; this is not a real-time SLA. The database lease prevents overlapping refreshes, and cleanup runs at most hourly. The optional `python -m scripts.run_feed_and_mail_worker` supplies a more frequent supervised worker on an always-on host. Mail and intelligence remain separate jobs. `FEED_REFRESH_MODE=daily` retains the optional 08:00 India-time sweep. Owner-authenticated `POST /api/admin/refresh?source=<id>` can check an eligible individual source.

Morning dispatch uses the subscriber's IANA timezone. Gmail processes up to three mailboxes per invocation. Resend can process up to ten batches of 100 per invocation within the worker time budget. The batch and related reservations commit before any network call. Transient failures retry the identical request with its original idempotency key. Pending batches expire after 30 minutes or at the UTC quota boundary. Repeated failures and opted-out recipients are handled without blindly resending an uncertain batch. Recurring email includes one-click unsubscribe headers and a footer link.

Configure Resend delivery, bounce, and complaint webhooks at `POST /api/mail/events/resend` with `RESEND_WEBHOOK_SECRET`. The endpoint verifies the signature, deduplicates provider events, and suppresses bounced and complaining addresses. `GET /api/jobs/mail-health` requires the job secret and reports due and queued counts, oldest item age, batch outcomes, and provider event counts without recipient data. Alert on oldest due or queued age above 15 minutes, provider errors and unconfirmed batches, and prolonged feed staleness.

Common Reading Room pages use a one-minute archive cache and can serve the previous page while rebuilding it from the database. The visible Reading Room checks the stored first page and offers readers a button to apply updates. Reload archive bypasses the page cache and reads saved articles. Adaptive feed freshness uses the configured source cadence, with tolerance of at least 45 minutes or twice the interval. Daily mode uses a 45-minute grace period after the morning sweep. `GET /api/ready` returns HTTP 503 when all enabled feeds are stale or unavailable. `GET /api/health` checks API liveness and service configuration.

Global briefs use a five-minute cache and personal briefs use a 30-minute cache keyed by normalized inputs, including persona and ordered pins. Degraded briefs are cached for 60 seconds. The PostgreSQL lease blocks overlapping generation for identical settings. Configure `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` to reuse completed previews across Vercel instances. Without Redis, completed briefs are cached per warm process. Shared API rate limits and the daily synthesis quota live in PostgreSQL.

The homepage’s Top Stories uses the last 72 hours of independent reporting and limits the number of candidates per publisher. Reviewed developing stories in `app/headlines.py` have links, an update timestamp, and an expiration. Review those summaries against the linked reporting when extending or updating them. After adding publishers in `app/sources.py`, the next refresh populates their stories. To verify an immediate rollout, run the owner-authenticated `POST /api/admin/refresh` and check `/api/sources` and `/api/headlines`.

Personalization uses feed titles and excerpts. The summarizer skips headlines without excerpts, reuses successful summaries from the archive, and falls back to publisher material if synthesis fails. The curator can rerank the selected unpinned stories. The preview keeps the original source, headline, and publication date throughout. Model requests use bounded output, a 12-second SDK timeout, and one retry for fast connection or server failures. Global briefs and newsletter introductions are assembled without a model call.

Enable INFO-level application logs in your runtime to collect API request IDs, route templates, status codes, and timings. Application error logs record exception types. Treat `/api/ready` as archive readiness and `/api/health` as liveness and configuration status. The browser polls for updates when the first page is idle. The scheduled worker remains the durable refresh mechanism when the browser closes or the runtime ends a background task.

Source-specific freshness is visible in `/api/sources`. A feed that passes its check can have zero eligible items, including a preprint feed between publication cycles. Inspect `checked_at`, `last_success`, and article publication times when investigating a gap. The source catalog uses reviewed public RSS and Atom endpoints. Coverage, available history, languages, and update frequency vary by publisher. Search and briefs use available titles and excerpts, with links to the original reporting for full context.

Scheduled archive refreshes reuse `ETag` and `Last-Modified` when an RSS or Atom endpoint supplies them. The additive `brief_feed_validators` table stores these headers for up to six hours and scopes them to the reviewed feed and final same-host URL. A valid `304` updates freshness, leaves the articles in place, and keeps the last successful count. Failed downloads preserve the archive and the last successful validators. After repeated failures, `brief_feed_retries` defers checks for that source for up to one hour, or up to 24 hours when a publisher sends a longer valid `Retry-After`. Refresh calls respect the stored retry time and the source directory shows when the next check is eligible. A targeted owner refresh requests the complete response once the feed is eligible again. Run `POST /api/admin/setup` to create the tables before the first refresh. The application can also create them under an advisory lock on existing PostgreSQL deployments.

Owner setup attempts to install PostgreSQL `pg_trgm` and build a GIN index for normalized substring search. Its `search_index` field reports `trigram`, `unavailable`, or `portable` (SQLite). Search keeps the same matching and ranking with all three results. If setup reports `unavailable`, check the database role's extension and table privileges, then rerun setup during a low-traffic period. Initial index creation takes a write-blocking table lock.

The app keeps saved stories in browser storage. Saved stories are capped at 100 and stay on the originating browser. Search uses bounded, case-insensitive keyword matching with weighted ranking for matching titles and publishers. The current architecture does not provide cross-device reading history, synchronized personal preferences, full-article extraction, or per-reader scheduled AI synthesis. Scheduled mail sends the global edition.

## Technology discovery release — November 16, 2026

Run the owner-authenticated `POST /api/admin/setup` before opening the new application to traffic. The additive archive migration creates nullable `metadata_json` and `subject_keys` columns, backfills subject classification for retained rows, and preserves IDs, URLs, source ownership, mail records, and existing search columns. It uses the existing PostgreSQL advisory-lock boundary. New refreshes populate author names, tags, canonical publisher links, discussion URLs, and approved thumbnail URLs. Re-run setup if a rolling older deployment has inserted records without subject keys. No new service or environment variable is required.

The source registry supports RSS/Atom plus official DEV and Hacker News APIs. Hacker News retrieves bounded top/new/show lists and individual story records with six concurrent item requests, per-request timeouts, and a 12-second total deadline. Partial item failures preserve successful records. Both official API integrations can fall back to their own public RSS endpoint. If both transports fail, ingestion preserves the last successful archive and reports the failed check. Background refreshes keep the existing scheduler, lease, concurrency and serverless execution boundaries. Run `uv run python -m scripts.check_sources` for a read-only live integration audit; a healthy fetch can still contain old or zero eligible articles.

Hashnode's legacy `gql.hashnode.com` endpoint redirects to a paid-access announcement. Its current `gql-beta.hashnode.com` endpoint documents free anonymous `feed`, `user` and `tag` reads, while publication and individual-post reads are Pro-gated. Informa AI uses the free feed, never Pro-gated post queries, alongside the existing reviewed publication RSS. Medium uses reviewed publication/topic RSS, which does not include complete paywalled stories. See [Hashnode's current query access rules](https://github.com/Hashnode/gql-skill/blob/main/skills/gql-api/references/queries.md), [Medium RSS](https://help.medium.com/hc/en-us/articles/214874118-Using-RSS-feeds-of-profiles-publications-and-topics), [Forem API](https://developers.forem.com/api/v1), and [official Hacker News API](https://github.com/HackerNews/API).

The new subject filter applies to search, pagination, saved views and digest generation. Keywords, authors and tags are searchable in both archive and direct-feed modes. Search remains database-backed keyword matching rather than semantic vector search. For You selects from a bounded, per-source-and-topic pool from the last seven days. It uses explainable preference weights, freshness, small engagement signals, source diversity and canonical URL deduplication. Distinct reporting on the same event stays separate. Recommendations do not consume AI tokens. Browser preferences are local and submitted only when requesting rankings; the server does not create accounts or store preference identities.

The reader defaults to short supplied excerpts, publisher attribution and original links. It distinguishes publisher reading-time estimates from excerpts and does not display generated impact claims unless supplied by the existing AI briefing pipeline. Complete text can be displayed only through an active owner-reviewed reading permission. One-story AI briefs still use publisher excerpts and the existing quota, structured-output validation, caching and fallback behavior. Requests never fetch an arbitrary article URL. Thumbnails are restricted to reviewed HTTPS hosts in both application validation and the CSP; the frontend uses lazy loading and `no-referrer`.

When deploying, verify migration, `/api/sources`, subject search, `/api/recommendations`, `/api/articles/{id}` and a global brief independently of Vercel's Ready status. The CI PostgreSQL job rehearses the archive upgrade on an isolated service. Browser automation may be unavailable in a restricted desktop session; record that limit separately from successful API and asset checks. UI source wiring is checked during `npm run build`, including literal element references in the entry scripts.

Before opening 10,000 daily subscriptions, run the PostgreSQL rehearsal in CI, provision a provider allowance for at least 300,000 digests per 30 days plus verification and on-demand traffic, and verify the sending domain and its SPF, DKIM, and DMARC records. Connect webhooks, supervise the always-on worker, and ramp up with a consented cohort while measuring end-to-end lag and provider delivery and complaints. The synthetic rehearsal proves database fan-out and duplicate prevention, with a fake provider and no real recipients. It does not measure inbox placement or production throughput.

Workspace dispatch accepts supported HTTPS Slack Incoming Webhook and Teams Workflows URLs. The supplied secret URL only lives for the delivery request. The stored record uses its hash. Teams Workflows must be configured to accept webhook requests for the target channel.

## Public community discovery and reading permissions

Apply `POST /api/admin/setup` before enabling the delivery receipt release. The additive `brief_mail_outcomes` table stores signed provider message outcomes for 30 days, without recipient addresses. Configure Resend to send `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.failed`, `email.bounced`, `email.complained` and `email.suppressed` to `/api/mail/events/resend` and set its signing secret as `RESEND_WEBHOOK_SECRET`. The provider message ID connects the event to a verified reader's receipt. The browser checks for up to one minute while visible and provides a manual status check afterward. Gmail and other transports retain acceptance-only receipts. A delivered event confirms acceptance by the receiving mail server. Inbox placement must be checked with a consented test recipient.

The Hashnode connector requests up to six pages of 20 records within an 18-second overall deadline, preserving completed pages when later requests fail. Requests go only to the fixed public endpoint. Future-dated records, records older than 30 days, unsafe links and out-of-scope articles are rejected. The connector requests metadata and briefs, not complete article bodies. Community feeds can contain spam, inaccuracies or paid content; a record's presence is not an independent verification of its claims. Since the API does not supply language metadata, these records use `und` rather than claiming English.

The expanded Medium catalogue adds ProAndroidDev, Level Up Coding and Towards AI, plus software engineering, system design, DevOps, data engineering and machine learning topic feeds. Canonical identity rules preserve a single archive owner for overlapping feeds. Author identity uses a supplied public profile when available; otherwise a reported RSS name is scoped to its source feed. Individual feeds and author identities can be followed in browser preferences. These controls save preferences in the current browser, without changing an external account or creating an email subscription.

Run owner-authenticated `POST /api/admin/setup` for the additive `brief_contributions` and `brief_reading_permissions` tables before checking the author workflow. Cold starts also create these tables safely under the existing advisory-lock boundary. No existing article or mail table is replaced. Public submission requires the existing verified-inbox configuration: `NEWS_DATABASE_URL`, `PUBLIC_EMAIL_ENABLED`, `PUBLIC_ORIGIN`, `MAIL_SESSION_SECRET`, Turnstile keys and a working email transport. No Hashnode key, Pro plan or new paid service is needed. The author workspace reports if verification is unavailable.

Authors open `/contribute.html?article=<existing-article-id>`, verify their inbox, submit text and permission evidence, and explicitly accept the displayed version of the permission statement. Verification alone neither sends a digest nor creates a subscription. All submissions start private and pending. The owner opens the editorial review section with `ADMIN_TOKEN`, checks the verified contact and evidence, and explicitly confirms permission before approving. The key is held only in page memory. Submissions retain their permission-statement version, evidence and review/withdrawal history. Authors can withdraw; owners can revoke. A withdrawn submission cannot be reapproved, and withdrawing an older submission cannot revoke its newer replacement.

Reading grants are stored independently from feed metadata, so an upstream record cannot declare itself licensed. Details recheck the active grant and use `no-store`; revoked text disappears on the next request. Already viewed text cannot be recalled from a user's open page or copies. Private review records remain in the archive after withdrawal. The app does not automatically verify legal ownership, acquire publisher licences, republish paywalled material, or turn an arbitrary URL into a new article. Editorial review must establish actual permission before any real content is published.

For local validation, use Node 24.15+ in the 24.x LTS line, `npm ci`, `npm test`, `npm run lint`, `npm run build`, `uv run ruff check app tests scripts main.py` and `uv run pytest -q`. DOM tests exercise actual reader and author workspace modules with mocked transport. CI also runs the permission lifecycle on isolated PostgreSQL. Full visual browser QA and actual verification-mail delivery remain separate checks.
